# 网络与媒体使用说明

## 选择网络方式

从图库右上角进入网络设置。应用提供四种模式：

| 模式 | 行为 |
| --- | --- |
| 进程环境 | 使用启动进程的 HTTP_PROXY/HTTPS_PROXY/NO_PROXY 等环境设置；不是系统 PAC 自动检测 |
| 直连 | 不指定应用级代理；设备已有的 VPN/TUN 路由仍由系统处理 |
| HTTP | 所有应用读取通过填写的无认证 HTTP 代理，HTTPS 使用 CONNECT |
| SOCKS5 | 通过无认证 SOCKS5 代理；目标域名交给代理解析 |

主机和端口分开填写，例如 `127.0.0.1`、`10808`。端口对应的协议必须与代理软件的监听设置一致。该默认地址只是表单初值，不会自动打开手动代理。

`127.0.0.1` 指正在运行应用的设备。Android 上填写它表示手机本机；若使用电脑提供的局域网代理，应填电脑的实际局域网地址和允许该设备访问的监听端口。

当前版本不支持需要用户名/密码的代理或 PAC 脚本，设置中不保存代理凭据。Web 由浏览器决定代理，应用无法修改浏览器的代理或 CORS 规则，因此只显示说明和连接检查。

## 设置生效与故障反馈

保存设置会取消旧连接，使新请求使用新配置。图片缓存仍可复用；重新加载的资源走当前网络设置。

- 手动代理连接失败时不会退回直连。
- TLS 证书验证始终开启；证书错误、代理错误、超时、权限状态与限流应分别处理。
- 已保存配置损坏时保留原文并提示重新保存，不静默改变网络方式。
- API 和 CDN 分开诊断，便于判断“帖子列表能开但图片不能开”的情况。检查结果不包含账号、密码或完整请求参数。
- GET 的临时错误会有限重试，并遵守有限截止时间和 Retry-After；刷新失败保留已显示作品。

匿名访问受到的站点权限限制不能靠代理解决。当前应用还没有站点账号/API key 配置。

## 媒体与保存

图片、Ugoira 和文件保存使用统一网络服务。原生视频先经该服务缓存，再交给平台播放器播放本地文件；首次播放需等待下载，这是为了让视频遵守相同代理策略。

| 平台 | 保存和播放行为 |
| --- | --- |
| Android / iOS | 图片与视频分别保存到相册；系统首次使用可能询问相册权限 |
| macOS | 使用平台可用的相册与播放器能力；用途描述和 release 网络权限随应用提供 |
| Windows / Linux | 保存到 Downloads 下的 DanbooruViewer 目录；无内置视频后端时可用系统播放器打开已缓存本地文件 |
| Web | 图片使用浏览器可用的数据提供器；保存交给浏览器，受站点 CORS 与浏览器下载策略约束 |

批量保存是前台队列。窗口中显示每项结果，取消会中止当前下载并停止后续项；重试只处理未完成项。关闭结果后保留未完成项的选择。它不宣称支持后台跨重启恢复。

Web 保存需要在浏览器内形成文件缓冲，单次保存设有大小上限；超过上限会提示打开原链接下载。Ugoira 也有压缩包、帧数与解码预算，超限会显示错误，不无限扩大内存。

## 验证边界

本地假代理/HTTP 服务与 Flutter 测试可以验证路由、取消、错误处理和交互；它们不能替代目标设备上的真实 VPN、相册权限、硬件视频解码和系统外部播放器测试。发布记录应分别注明这些结果。
