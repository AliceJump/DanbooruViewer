## 实测空间

以下是控件树中 `GridView` 的实际逻辑高度；视口没有额外模拟系统状态栏或
导航栏，不能直接作为某台实体手机的像素测量。

| 逻辑视口 | 展开时图库高度 | 收起后图库高度 | 增加 |
| --- | ---: | ---: | ---: |
| 375 × 812 | 575 | 756 | 181（31.5%） |
| 320 × 568 | 331 | 512 | 181（54.7%） |
| 568 × 320、200% 字号 | 81.56 | 264 | 182.44（223.7%） |

收起后保留顶部的一行搜索摘要、搜索入口、设置和收藏入口；图库继续沿用
原滚动位置（在新布局的有效范围内）。如果视口变高后旧位置超出新的最大
偏移，则停在新的列表末尾；这类布局修正不计入用户的滚动距离。搜索草稿
与标签在收起、展开之间保留。短横屏展开时搜索区域仍有独立滚动边界，避免大字体把图库
完全挤出视口。原始测量见 [measurements.json](measurements.json)。

## 渲染与检查

临时 widget-test harness 以设备像素比 1 布局，通过
`RenderRepaintBoundary.toImage(pixelRatio: 2)` 输出 PNG。
测试字体使用本地 Noto Sans CJK 与 Material Icons，不改变产品主题或依赖。
图片先写入应用的真实缓存，再由正常的 Flutter 图片组件读取解码；导出前
断言所有已构建缩略图均有已解码的 `RawImage.image`，并确认没有布局异常。

这组截图关闭系统动画，分别保留初始展开状态和图库向下滚动后的最终状态。
六张图均已逐张目视检查。滚动阈值、焦点保护、手动恢复、键盘快捷键、
宽屏与分页行为由独立控件回归测试验证；截图本身不代表实体 Android
设备上的动画流畅度或网络延迟测试。
